# Аналіз та порівняння алгоритмів сортування: Insertion Sort, Merge Sort та Timsort

У даному дослідженні на практиці перевірили три алгоритми сортування:
1. Сортування вставками (Insertion Sort)
2. Сортування злиттям (Merge Sort)
3. Timsort (алгоритм, який використовується для sorted() або .sort() у Python)

## Проведені тести

## Спостереження
1. Сортування вставками (Insertion Sort)
Перевага: Працює миттєво на зовсім маленьких списках або коли дані вже майже відсортовані.
Недолік: На великих масивах швидко "вмирає". Причина — квадратична складність часу $O(N^2)$.

2. Сортування злиттям (Merge Sort)
Перевага: Працює стабільно і передбачувано. Навіть на великих масивах витрачає частки секунди. Має часову складність $O(N \log N)$ незалежно від початкового стану даних
Недолік: Робить багато зайвої роботи на вже відсортованих даних і витрачає додаткову пам'ять, бо постійно ділить масив навпіл і збирає його знову.

3. Timsort
Timsort — це гібрид кількох підходів. Він бере найкраще від двох попередніх методів: Якщо дані вже в порядку, він практично не витрачає часу на їх обробку — час роботи $O(N)$. Для маленьких шматочків списку він використовує просте сортування вставками (бо воно швидко працює на малих обсягах без накладних витрат), а потім об'єднує ці шматочки за принципом сортування злиттям.

# Підсумок

Вбудований у Python алгоритм Timsort показє себе ефективно на будь-яких типах і кількостях даних. Окрім продуманої логіки, Timsort написаний мовою C всередині самого інтерпретатора Python, що дає йому додатковий величезний прирост у швидкості. Саме тому в реальній розробці завжди варто використовувати стандартні sorted() та .sort().
